## §2 무엇을 바꾸는가 — **한 가지뿐**

**v1 레시피를 그대로 고정한다.** 베이스 `Qwen3.5-9B`, LoRA rank 16, **lr 2e-4**,
데이터 `train_v3.jsonl` / `val_v3.jsonl`(내용 동일), 배치 8 × 누적 2, 시드 42.

**바꾸는 것: 학습 프롬프트의 입력 형식.**

| 항목 | v1/v3/v4 | **V5-A** |
|---|---|---|
| 프롬프트 | 코드 1개만 | 코드 1개 + **상대 판본과의 차이 블록** |
| 쌍 없는 샘플 | — | 차이 블록 자리에 **`(none)`** |
| 출력 서식 | 4줄 | **동일** |

**형식은 Phase 1 판정에 따라 정한다 (결과 전 고정 규칙):**
- `PROMPT-PARTIAL` → **그 arm 의 형식**을 그대로 학습 형식으로 쓴다.
- `PROMPT-NULL` → **P1**(코드 + 끝에 차이 블록). 제품 PR 경로와 형태가 가장 가깝기 때문이다.

**어제 V4-TRAIN 의 실패를 반복하지 않는다.** V4 는 학습량과 lr 을 함께 바꿔
DOSE 외삽 검정을 오염시켰다(D-17). **이번에는 형식 하나만 바꾼다.**

**V5-B(쌍 대조 랭킹 손실)는 오늘 하지 않는다.** 구현 위험이 크다.
V5-A 가 `NO-ADOPT` 로 끝나면 다음 세션 후보로 기록한다.

## §3 누수 규칙 — Phase 1 과 동일 (D-20)

학습 프롬프트에도 그대로 적용한다: `Version A`/`Version B` 중립 라벨, 배정 무작위(seed 42),

## §4 미리 인정하는 한계 — **학습 쌍이 전부 (취약, 안전) 이다**

`train_v3` 의 1:1 쌍 5,533개는 **전부 한쪽이 취약하고 한쪽이 안전**하다.
**"둘 다 안전한 변경"(리팩터·기능 추가) 쌍이 하나도 없다.**

→ **위험: 모델이 "차이 블록이 있으면 둘 중 하나는 취약하다"를 배울 수 있다.**
그러면 PR 마다 무언가를 지목하는 과잉 경보 기계가 된다.

**검증 방법 (결과 전 고정).** 문헌적으로 안전한 safe-safe 쌍 데이터가 우리에게 없으므로,
**대체 지표 두 개**로 이 위험을 직접 잰다.

| 지표 | 정의 | 판정선 |
|---|---|---|
| **FPR-safe** | 평가 쌍의 **안전 판본**들만 모아 τ=0 에서 "취약"이라 답한 비율 | v1 대비 **+0.05 이내** |
| **차이-유무 편향** | 차이 블록이 있는 입력(쌍 세트)과 없는 입력(`(none)`, 단건 회귀 세트)의 "취약" 판정률 차이 | v1 의 같은 차이보다 **커지지 않을 것** |

**왜 safe-safe 쌍을 만들지 않는가 (그대로 적는다).** CleanVul/PrimeVul 은 쌍마다
(취약본, 패치본) 구조라 **양쪽이 안전한 쌍이 데이터에 존재하지 않는다.**
유사도로 억지로 구성하면 서로 무관한 저장소의 코드가 묶여 **"같은 함수의 두 판본"이 아니게 된다.**
그건 다른 것을 재는 것이므로 하지 않는다. **대신 위 두 지표로 같은 위험을 잰다.**
이것은 완전한 대체가 아니다 — **한계로 남긴다.**

## §5 사전 등록 게이트

**MID-GATE (step ≈ 750, 첫 저장 체크포인트 기준).**
CleanVul_v2 tune 의 **유사도 0.95+ 쌍**에서 순위 정확도를 재고,
**v1 대비 +0.05 미만이면 즉시 terminate**(`MID-GATE-STOP`).
- v1 기준선은 **같은 형식·같은 채점 조건에서 Phase 1 이 낸 P0 값**을 쓴다.
- 점추정으로 판정한다. 이유는 어제 §10-1 과 같다 — **게이트는 성능 판정이 아니라 예산 방어**다.

**최종 판정.**

| 판정 | 조건 |
|---|---|
| **ADOPT-PR** | ① 0.95+ 쌍 순위 정확도(엄격) **≥ 0.60** AND ② P-shuf **≤ 0.55** AND ③ 단건 회귀 **−0.02 이내** AND ④ **FPR-safe ≤ v1+0.05** |
| **ADOPT-ALL** | ADOPT-PR **AND** 전체 CleanVul_v2 / PrimeVul report AUC 가 v1 대비 **쌍 부트스트랩 ΔAUC CI 하한 > 0** |
| **NO-ADOPT** | 그 외 → **v1 유지** |

**`ADOPT-PR` 은 "PR 모드 한정 채택"이다.** 전체 SAST(`/analyze`)에는 적용하지 않는다 —
그 경로에는 상대 판본이 없어 학습 형식과 입력 형식이 어긋난다.

## §8 이 실행이 답하지 못하는 것 (미리 적는다)

- **시드 1개.**
- **safe-safe 쌍이 없다**(§4). 과잉 경보 위험은 대체 지표로만 잰다.
- **PR 모드 한정.** 전체 SAST 경로는 이 형식을 쓸 수 없다.
- **형식 학습과 능력 학습을 분리하지 못한다.** 좋아져도 "diff 를 읽는 능력이 생겼다"인지
  "형식에 익숙해졌다"인지 이 실행 하나로는 못 가른다. 후자를 배제하려면
  **학습에 쓰지 않은 다른 diff 형식**에서도 개선이 나와야 한다 — §7 에 P0 도 함께 채점하는 이유다.

## §10 사전등록 추가 — **기준선 교체와 학습량 상한** (Phase 2 실행 전 기록)

### §10-1 기준선을 v1 → **v3s42@step750** 으로 바꾼다

로컬에 `rebuild/out/v3_s42_step750/` 이 남아 있다. 이것은
**v1 과 같은 레시피(베이스·rank 16·lr 2e-4·`train_v3` 데이터·시드 42)로 750 step 학습한 어댑터**다.

**v5 를 같은 750 step 으로 학습하면, 두 모델의 차이는 입력 형식 하나뿐이 된다.**

| 비교 | 다른 것 |
|---|---|
| v5 vs **v1** | 학습량 · 데이터 구성 · 형식 (셋) |
| v5 vs **v3s42@750** | **형식 하나** |

**v1 은 배포 기준선으로 계속 병기**한다(제품 판단에 필요하므로).
**그러나 "형식이 효과가 있는가"의 판정은 v3s42@750 대비로 한다.**
어제 D-17 이 "한 번에 하나만 바꾼다"를 어겨서 검정이 오염됐던 것을 반복하지 않기 위해서다.

### §10-2 학습량을 **750 step** 으로 고정한다 (2 epoch → 약 0.9 epoch)

**이유는 시간이다. 그대로 적는다.** 로컬 킬스위치가 **18:58 KST** 에 발화하고, 지금이 14:4x 다.
A100 기준 750 step ≈ 2시간 + 채점 30분 → **약 18:00 종료**로 여유가 남는다.
2 epoch(1,674 step)는 4.5시간이라 **킬스위치를 넘긴다.**

**이 선택이 만드는 한계.**
- **수렴한 모델이 아니다.** 어제 V4 도 같은 이유로 중단됐고, 같은 서술 규칙을 따른다 —
  **"완주"라고 쓰지 않고 도달 step 을 적는다.**
- 다만 **비교 대상(v3s42)도 정확히 750 step** 이므로 **이 비교 자체는 공정하다.**
  "형식이 750 step 시점에 효과가 있는가"에는 답할 수 있고,
  **"수렴 후에도 그런가"에는 답하지 못한다.**

### §10-3 MID-GATE 기준선도 함께 바꾼다

§5 의 MID-GATE 는 "v1 대비 +0.05"였다. **`v3s42@750` 대비 +0.05 로 바꾼다.**
같은 이유(단일 변수)이며, **완주 판정선(ADOPT-PR / ADOPT-ALL)의 숫자는 그대로 둔다.**

단, 750 step 고정이면 MID-GATE(step≈750)와 종료가 같은 지점이 된다.
따라서 **MID-GATE 를 step 450 으로 앞당긴다** — 그 시점에 `v3s42@450` 이 없으므로
**절대 기준(0.95+ 쌍 순위 정확도 ≥ 0.50)** 으로 판정한다.
0.50 은 우연 수준이다. **거기에도 못 미치면 형식 학습이 역효과라는 뜻이므로 즉시 중단한다.**
