## §4 누수 규칙 (D-20) — 어기면 그 arm 무효

벤치 쌍은 **취약 = 이전 판본, 안전 = 이후 판본**이다. 형식이 그 순서를 흘리면 안 된다.

1. 두 판본은 **`Version A` / `Version B`**. **어느 쪽이 A 인지 쌍마다 무작위**(seed 42).
2. **금지어**: `previous, current, before, after, fix, fixed, patch, patched, commit, old, new, original, updated`.
   diff 블록 제목은 **"Lines that differ between Version A and Version B"**.
   `-` 는 "only in Version A", `+` 는 "only in Version B" 로 **명시**한다 — A/B 가 무작위이므로 방향은 라벨 정보를 담지 않는다.
3. **양방향 채점**: 각 쌍에서 A 를 묻는 프롬프트와 B 를 묻는 프롬프트를 **각각 1회**.
4. **P-shuf 대조군**: 라벨을 무작위로 섞은 사본에서 같은 지표를 낸다.
   **순위 정확도 > 0.55 → 그 arm 무효**(형식이 라벨을 흘린 것).

## §5 arm (같은 400건, 같은 채점기 `score_logprob`)

| arm | 형식 |
|---|---|
| **P0** | 현행 프롬프트. 판정 대상 판본만 제시 (기준선) |
| **P1** | P0 + 끝에 `Lines that differ between Version A and Version B:` 블록(hunk, `-`/`+`) |
| **P2** | 판정 대상 본문 안에서 변경 줄 **앞 줄에** 언어별 주석으로 `[DIFF]` 마커 |
| **P3** | Version A 전체 + Version B 전체를 모두 제시하고 `Assess Version {X}` |
| **P1-shuf / P3-shuf** | P1·P3 에 라벨 셔플 적용 (누수 대조군) |

**공통:** `MAX_LEN = 8192`. P3 는 두 판본을 함께 넣어 16.3% 가 3,500 토큰을 넘기 때문이다.
**P0 도 같은 8192 로 다시 채점한다** — arm 간 절단 조건을 맞추기 위해서다
(어제 v1 점수는 4096 이라 그대로 재사용하지 않는다. 재현 대조용으로만 병기).

**P3 의 범위 제한:** 두 판본이 다 있어야 하므로 **PR 모드에서만 가능**하다.
전체 SAST(`/analyze`)에는 다른 판본이 없다. **어느 arm 이 이겨도 "PR 모드 한정 개선"으로 적는다.**

## §8 이 실험이 답하지 못하는 것 (미리 적는다)

- **PR 모드 한정.** P3 는 전체 SAST 에 적용할 수 없다. P1/P2 도 diff 가 있어야 한다.
- **모델은 diff 없는 프롬프트로 학습됐다.** diff 를 넣으면 형식이 학습 분포 밖으로 나간다.
  **결과가 나빠도 "diff 가 도움이 안 된다"로 읽을 수 없다** — 형식 이탈과 구분되지 않는다.
  이 교란은 Phase 2(같은 형식으로 학습)에서만 풀린다.
- **유사도 0.95+ 구간만 잰다.** 그 아래 구간에 대한 효과는 재지 않는다.
- **표본 200쌍.** 층별로는 10~120쌍이라 내부 test 층(10쌍)은 사실상 참고값이다.
- **근사 중복 누수**(Phase 0-d): 내부test 0.00% / CleanVul 0.00% / PrimeVul **1.04%**.
  전부 5% 미만이라 제외 부분집합을 따로 만들지 않는다. **다만 이 수치는 하한**이다
  (3-shingle 역색인 + 상위 20 후보만 확인 — `phase0_materials.json` 의 한계 서술).

## §10 사전등록 추가 — **위치 상쇄 재측정** (Phase 1 결과를 본 뒤 추가. 그 사실을 명시한다)

### §10-1 왜 추가하는가 — 내 누수 검정이 한 가지를 못 잡았다

Phase 1 은 §7 규칙대로 계산하면 **`PROMPT-WIN` (P3, 순위 0.62)** 이 나온다.
P-shuf 도 통과했다(P3shuf 0.48 ≤ 0.55).

**그런데 사후 점검에서 형식이 만든 다른 편향이 드러났다:**

| arm | P(score(A) > score(B)) (라벨 무관) | vuln=A 쌍 정확도 | vuln=B 쌍 정확도 | 격차 |
|---|---|---|---|---|
| P0 | 0.3200 (동점 0.33) | 0.4330 | 0.4854 | −0.05 |
| P1 | **0.7000** | 0.7835 | 0.3204 | **+0.46** |
| P2 | 0.3550 | 0.5258 | 0.6505 | −0.12 |
| P3 | **0.7350** | **0.8969** | **0.3592** | **+0.54** |

**P1·P3 는 "Version A 를 더 취약하다고 본다"는 위치 선호를 만든다.**
A/B 배정이 무작위(97/200 이 vuln=A)라 전체 정확도가 0.62 로 나왔지만,
**그 값은 위치 선호와 배정 비율의 곱에 크게 좌우된다** — 배정이 p·0.897+(1−p)·0.359 이므로
p 가 0.4↔0.6 이면 0.574↔0.682 로 흔들린다.

**P-shuf 는 이걸 못 잡는다.** 라벨을 섞으면 내용 신호는 상쇄되지만 위치 선호는 라벨과 무관해
그대로 0.5 근처가 나온다. **내 §4-4 누수 검정의 설계 결함이다.**

### §10-2 기준을 바꾸지 않는다. **측정을 고친다**

- §7 의 판정선(0.60/0.53/0.55)과 §4 규칙을 **그대로 둔다.**
- Phase 1 의 계산된 판정 **`PROMPT-WIN`(P3) 을 결과로 기록한다.**
- **다만 그 판정에 근거해 행동하지 않는다** — Phase 2 생략도, 제품 반영도 하지 않는다.
  **계측기에 알려진 결함이 있는 상태의 값이기 때문이다.**
- 같은 가설을 **위치 상쇄 설계**로 다시 잰다. 이건 기준 변경이 아니라 **새 측정**이다.

### §10-3 위치 상쇄 설계 (실행 전 고정)

같은 200쌍을 **두 배정 모두**로 만든다:
- 배정 X: 취약본 = Version A
- 배정 Y: 취약본 = Version B

각 배정에서 양방향 채점(A 판정 1건 + B 판정 1건) → **쌍당 4건**, arm 당 **800건**.
대상 arm: **P1 · P2 · P3** (P0 는 A/B 개념이 없어 상쇄가 불필요 — 기존 400건을 그대로 쓴다).

**지표.**
- `acc_X`, `acc_Y` 를 각각 내고 **`acc_cb = (acc_X + acc_Y) / 2`** 를 주 지표로 한다.
  더해지는 위치 항이 있으면 두 배정에서 부호가 반대라 **상쇄된다.**
- **`pos_gap = |acc_X − acc_Y|`** 를 함께 보고한다. **이 값이 형식이 만든 위치 편향의 크기다.**
- 쌍 부트스트랩 CI 2,000회(쌍 단위 — 같은 쌍의 4건은 함께 재표집).

**판정 (사전 고정).**

| 판정 | 조건 |
|---|---|
| **CB-WIN** | `acc_cb` **≥ 0.60** AND `pos_gap` **≤ 0.20** AND 동점률 ≤ 0.10 AND 해당 arm 의 P-shuf ≤ 0.55 |
| **CB-PARTIAL** | `acc_cb` **0.53 ~ 0.60** AND `pos_gap` ≤ 0.20 |
| **CB-NULL** | 그 외. **`pos_gap` > 0.20 이면 `acc_cb` 가 아무리 높아도 여기로 간다** |

`pos_gap ≤ 0.20` 을 넣는 이유: 상쇄로 평균은 맞출 수 있어도, **한쪽 배정에서 0.36 인 시스템은
실제 PR 에서 절반의 경우 우연 아래**다. 평균만 보고 배포하면 안 된다.

**비용:** 2,400건 ≈ 10분, A6000 $0.53/hr 기준 **약 $0.09.**

### §10-4 이 추가가 인정하는 것

**결과를 본 뒤에 추가한 절이다.** 그 사실을 숨기지 않는다.
추가한 것은 **판정선이 아니라 계측 방법**이며, 원래 판정(`PROMPT-WIN`)도 **지우지 않고 남긴다.**
§10 이 없었다면 이 세션은 **위치 편향을 diff 이해로 잘못 보고했을 것이다.**
